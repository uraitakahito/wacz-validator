## What wacz-validator is

A **producer-independent validator** for [WACZ](https://specs.webrecorder.net/wacz/1.1.1/)
— the format that packages WARC data and its metadata into a ZIP file. Point it
at an archive and it reports, rule by rule, what conforms and what does not.

Producer-independent means it makes no assumptions about which tool wrote the
archive. It reads the ZIP as WACZ 1.1.1 describes it, so a WACZ from any recorder
is judged the same way.

## Two things it is not

It does not **replay** archives — that is [ReplayWeb.page](https://replayweb.page/)'s
job. And it does not **produce** them; when this site mentions
BrowserHive, that is a separate
project whose BrowserHive WACZ files wacz-validator happens to check.

## How it is put together

```mermaid
flowchart LR
    tui["@wacz-validator/tui (bin: wacz-validator)"] ==>|"WS / JSON-RPC"| daemon["@wacz-validator/daemon"]
    browser["capture-workbench (a browser client)"] -->|"REST"| daemon
    cli["@wacz-validator/validate-cli (bin: wacz-validator-validate)"] -->|validates with| core["@wacz-validator/core"]
    daemon -->|validates with| core
    tui -->|import| protocol["@wacz-validator/protocol"]
    daemon -->|import| protocol
    protocol -.->|"import type only"| core
    core -->|import| shared["@wacz-validator/contract"]
    protocol -->|import| shared

    classDef shared fill:#fff3cd,stroke:#d4a72c,color:#5c4500;
    class shared,protocol shared;
```

The daemon is **stateless**, which is what lets a browser client —
[capture-workbench](https://github.com/uraitakahito/capture-workbench) — call the same handlers as
the terminal UI, over HTTP instead of the WebSocket. See [Architecture](/wacz-validator/architecture/).
